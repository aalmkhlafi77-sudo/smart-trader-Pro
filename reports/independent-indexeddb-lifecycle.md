# تقرير مستقل — إصلاح دورة حياة IndexedDB وذرّية حذف الحمولة

التاريخ: 2026-09-21  
الفرع: `codex/indexeddb-lifecycle`  
نقطة البداية: `2442554` (`docs: plan indexeddb lifecycle repair`)

## الحكم التنفيذي

تم تنفيذ المهمة الثالثة المعتمدة بنجاح:

- أصبح مستودع IndexedDB يعيد استخدام اتصال واحد بعد التهيئة، مع إغلاق صريح عند الحاجة، ومعالجة `versionchange`.
- أصبح حذف تشغيل تكلفة الحمولة ذرياً عبر مخازن التشغيل والعناصر والأسطر والتوزيعات الأربعة.
- لا تُرسل إبطالاً للمستهلكين إلا بعد اكتمال المعاملة؛ وعند الإلغاء تبقى البيانات والإبطال بلا تغيير.
- لم يتغير مخطط قاعدة البيانات أو رقم إصدار المخطط أو منطق التسعير أو سلوك واجهة React خارج نطاق دورة الاتصال والحذف.

## التشخيص قبل الإصلاح

كان كل استدعاء لمساعد القراءة يفتح اتصال IndexedDB جديداً، ثم يغلقه بعد اكتمال العملية. اختبار RED المخصص أثبت فتح ثلاثة اتصالات جديدة عند تنفيذ ثلاث قراءات متوازية، كما أثبت غياب واجهة الإغلاق الصريح.

وكان حذف تشغيل تكلفة الحمولة ينفذ حذف الأب والأبناء في معاملات منفصلة. اختبار RED المخصص أثبت عدم وجود معاملة متعددة المخازن، كما أثبت أن إلغاء العملية لا يعيد الحالة الذرية المطلوبة.

## الإصلاح المنفذ

### دورة الاتصال

- إضافة تخزين مؤقت للاتصال ووعد الفتح الجاري لمنع الفتح المتكرر.
- إضافة `closeIndexedDbConnection()` كحد صريح لدورة الحياة.
- ربط `versionchange` بإغلاق الاتصال وإبطال التخزين المؤقت.
- إزالة الإغلاق بعد كل عملية قراءة أو كتابة.
- جعل أخطاء الطلب والمعاملة والإلغاء تصل إلى المستدعي بدلاً من إكمال العملية بصمت.
- تحديث اختبارات قواعد البيانات التي تحذف قاعدة الاختبار لتغلق الاتصال أولاً.

### الحذف الذري

ينفذ `deleteCargoCostRun` حذف الأب والأبناء في معاملة `readwrite` واحدة تشمل:

1. `cargoCostRuns`
2. `cargoCostItems`
3. `cargoCostLines`
4. `cargoCostAllocations`

يُبث إبطال بيانات الحمولة فقط بعد اكتمال المعاملة. واختبار الإلغاء يثبت بقاء الأب وجميع السجلات التابعة وعدم إرسال أي إبطال.

## بوابات الاختبار

### اختبار RED

قبل الإصلاح فشل `connectionLifecycle.test.ts` بسبب فتح ثلاثة اتصالات جديدة، وبسبب عدم وجود دالة الإغلاق. كما فشل `cargoCascadeAtomicity.test.ts` لغياب المعاملة متعددة المخازن ولأن سيناريو الإلغاء كان يكتمل بدلاً من رفضه.

### اختبار GREEN المركز

نجحت الاختبارات المركزة بعد الإصلاح:


وشملت دورة الاتصال، ذرية الحذف، الحذف القائم، مستودع الإبطال، وتكامل الإبطال.

### البوابات الكاملة


فشل فحص الترجمة مطابق لخط الأساس المعروف، ومحصور في مفاتيح موجودة مسبقاً في `cargoDecisionReports` و`indexedDbRepository` و`uiPreferencesStore`. لم تُضف هذه المهمة مفاتيح ترجمة جديدة ولم تُجرَ تعديلات لإخفاء الخط الأساس.

## المخاطر المتبقية وحدود التحقق

- يجب استدعاء الإغلاق الصريح عند حدود استبدال قاعدة البيانات أو عند إنهاء سياق اختبار/تشغيل يحتاج إلى تحرير الاتصال.
- لم تُضف مزامنة حالة عبر علامات تبويب متعددة؛ معالجة `versionchange` تضمن إخلاء الاتصال المحلي فقط.
- تم التحقق آلياً من إعادة الاستخدام والإلغاء الذري. ولم تُجرَ جلسة يدوية متعددة التبويبات ضمن هذه المهمة.

## قرار القبول

البنود الثلاثة الأصلية المتعلقة بهذه المهمة مكتملة: اتصال قابل لإعادة الاستخدام، حذف ذري، وبوابات تحقق موثقة. لا توجد مهمة رابعة ضمن النطاق المعتمد.
